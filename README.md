# 中医经方 · DeepSeek Harness 插件（dsh-jingfang）

把「经方问诊」做成一个可执行的流程插件：**先问清楚，再辨证，查得到文献才开方**。

**DSH Plugin**（`dsh.bundle.patch` + `dsh.client` 双面插件）· 适用于 DeepSeek Harness
· 仓库：[github.com/JamisBian/dsh-jingfang](https://github.com/JamisBian/dsh-jingfang)

**适用场景**：感冒发热、咳嗽咽痛、胃胀胃痛、腹泻便秘、失眠多梦、健忘乏力、头晕头痛、心悸胸闷、胁肋胀满、口干口苦、小便不利、水肿、关节疼痛、月经不调、痛经、更年期不适等——凡有明确「方证」可辨者，皆可用本插件走一遍问诊与核查。

- 患者端看到的是**选项卡片**（症状、舌象、脉象、鉴别点、候选方剂），不是一大段需要打字的问卷。
- 方证匹配、文献核查、开方是**三个独立的门槛**，任何一道过不去，都不会出方。
- 面对质疑有**「守正答辩」**工具：该坚持就摆出原文 + PMID，该认错就当场改方。

> ⚠️ 本插件是中医学习与辅助工具，输出**不能替代面诊与执业医师处方**。方中剂量按「1 两 = 3 克」折算，属临床保守换算；含毒性药的方剂必须在医师指导下使用。

## 它对应你提的六条

| 你的要求 | 插件怎么实现 |
| --- | --- |
| 1. 先问姓名、年龄、性别 | `jingfang_consult({stage:"intake"})` 弹出 6 个问题：称呼、年龄、性别、主诉、病程、特殊情况（妊娠/产后/哺乳等） |
| 2. 继续问哪里不舒服 | `intake` 的「主诉」是多选题 + 自由补充，覆盖 9 大类常见不适 |
| 3. 选项列表填具体症状、体温、血压、脉搏、脉象 | `stage:"symptoms"` / `"symptoms2"` / `"signs"` 共 21 题：症状 9 组多选（90 项症状 + 12 舌象 + 13 脉象）、体温/血压/脉搏区间选项 + 数值、舌象 12 项、脉象 13 项 |
| 4. 给出可能方剂，继续用选项列表确认 | `jingfang_differentiate`：先自动弹「鉴别要点」多选，再弹「候选方剂」单选（含匹配度与方证摘要） |
| 5. 查文献，确认有依据再开方 | `jingfang_evidence`：查内置《伤寒论》《金匮要略》条文 + 实时 PubMed；`jingfang_prescribe` 会**重新复核一遍**才出方 |
| 6. 没有文献支撑就换方，回到第 4 步 | `verdict ≠ supported` 时 `prescribe` 直接拒绝，并返回 `alternatives` 让流程回到 `differentiate` |

## 设计原则（写进引擎，不只是写进提示词）

1. **宁可多问，不可早断。**
   `differentiate` 内置置信度门槛：主症命中不足、最高匹配度 < 60%、或首选与次选分差 < 8%（高匹配时 4%）时，**拒绝给出方剂选项**，只返回下一轮鉴别问题（最多自动追问 3 轮）。信息不够时工具只会说「继续问」。
2. **提问一律用选项列表。**
   只有姓名、具体体温、血压、脉搏留自由填写；其余全部点选，且每题都带「以上都没有 / 没有测量 / 不清楚」的兜底选项。
3. **开方前必须患者确认。**
   `prescribe` 会先弹「确认开方 / 先看文献依据 / 换一个方 / 暂不开方」，不确认不出方。
4. **文献是硬门槛。**
   `supported` 需同时满足：① 条文原文中出现患者的阳性见症 ② 方证吻合度 ≥ 60%。只有 PubMed 现代研究（`modern-only`）**不算**支撑。工具离线时会如实标注「本次未联网」，绝不伪造文献。
5. **守正答辩：有定力，讲依据。**
   `jingfang_discuss` 面对患者质疑时：先自动查禁忌（妊娠/高血压/心脏病/糖尿病/出血/肾功能）与患者话里的新症状 → 该改就改并明确认错；否则维持原判，给出「方证要点 / 原文 / PubMed」三层依据，并用选项追问患者的依据来源与担心点。
6. **安全优先。**
   体温 ≥40℃、血压 ≥180/110 或 ≤85、脉搏 ≥130 或 ≤45、胸痛伴大汗、腹痛拒按伴高热、出血伴头晕等红旗，`prescribe` 直接拒绝并建议急诊。

## 安装

插件包声明了 `dsh.bundle.patch`（宿主工具）与 `dsh.client`（浏览器端卡片），
**没有构建步骤**——`lib/` 里就是可直接运行的 ESM 与手写 classic script，装完即用。

### A. 从 GitHub 仓库安装（推荐）

官方仓库：**https://github.com/JamisBian/dsh-jingfang**

**GUI**：侧边栏 **Plugins → Add plugin** → 粘贴任一写法：

```
https://github.com/JamisBian/dsh-jingfang
github:JamisBian/dsh-jingfang
JamisBian/dsh-jingfang
```

→ 点 **Install**，等 pnpm 拉取完成 → 在列表里对该插件选 **Enable now** → **重启应用**。

**命令行**（`DSH_HOME` 指向你实际在用的 profile 根）：

```bash
# Linux 原生 profile
dsh plugin --profile web add github:JamisBian/dsh-jingfang

# 桌面版（Windows 构建跑在 Wine 里，profile 在 Wine 的家目录）
DSH_HOME="$HOME/.wine/drive_c/users/$USER/.dsh" \
  dsh plugin --profile desktop add github:JamisBian/dsh-jingfang
```

装完 `dsh-jingfang` 会自动追加进 `dsh.profile.bundles`；**重启应用**后生效（profile 只在启动时组合）。

> 从 git 安装时 pnpm 会走 `prepare` 构建脚本，本包没有 `prepare`、也没有依赖，
> 正常不会触发 `allowBuilds` 提示。若你的 pnpm 版本仍拦了构建，按它打印的 key
> 加到 profile 的 `pnpm-workspace.yaml` 的 `allowBuilds` 下即可。

### B. 从本地路径安装（改代码时用）

```bash
# GUI：Plugins → Add plugin → 选仓库根目录（含 package.json 那一层）
dsh plugin --profile web add /path/to/dsh-jingfang
```

本地 `link:`/目录安装不会按 `files` 过滤，改完代码重载窗口即生效。

### C. 确认装好了

```bash
dsh --profile web --dump-config | grep dsh-jingfang   # 应能看到 jingfang 这一行
```

重启后输入框敲 `/`，菜单里应出现 **jingfang**；或直接说「我这两天头痛怕冷」。

## 病案导出

插件本身不落盘，病历只存在于会话记录里——删掉会话就没了。`jingfang_export` 解决留档：

```
~/中医病案/2026-11-20-张三.md
```

内容为「病史摘要 + 辨证结论 + 处方笺 + 医嘱」，同一患者复诊默认**追加**到同一文件，
形成连续档案。文件名会自动清洗掉 `/ \ : * ? " < > |` 等字符。

导出文件首行固定写入：

> 本文件含个人健康信息，请妥善保管，勿随意转发或上传。

## 一个细节：没有「留空」这一说

问到「还有什么要补充」这类开放题时，**空着提交会被界面拦住**。所以每道题都必须有选项——
最后一题也给了「没有补充 / 正在服药 / 有慢性病 / 有药物过敏史 / 近期手术 / 长期熬夜饮酒 / 工作久站久坐」多选。

其中「有药物过敏史」会单独存进病历的 `allergy` 字段，显示在病历摘要和处方笺的**用药警示首行**，
提醒逐味核对；这条有测试守着：任何一道题没有选项，测试直接失败。

## 怎么调用

插件装好后有**三个入口**，都指向同一套工具：

1. **斜杠命令（最直接）**：在输入框敲 `/jingfang` —— 技能以用户可调用方式注册，`/` 菜单里能选到。
   回车后本次会话即载入接诊流程，模型开始问「怎么称呼您」。
2. **说人话**：直接说「我这两天头痛发烧」「帮我看看这是什么证」——全局提示只有一句「遇到中医诉求先加载 jingfang 技能」，
   模型会自己加载，不会在普通写代码的会话里抢戏。
3. **模型主动加载**：技能同时是 `modelInvocable`，模型判断需要时会用 `skill` 工具加载。

> 为什么不全塞进系统提示：那会让每个会话都变成中医门诊。所以全局只留一句指引，
> 完整流程（问诊顺序、提问原则、守正答辩、开方门槛）放在 `jingfang` 技能里，按需加载。

## 用起来是什么样

```
你：我这两天感冒了
AI：（调用 jingfang_consult intake）
    ↳ 卡片：称呼 / 年龄 / 性别 / 主诉 / 病程
你：陈小明，38，男，感冒发热，2–3 天
AI：（symptoms → symptoms2 → signs 三张卡片，逐项勾选）
    ↳ 体温 37.8、血压 118/76、脉搏 82、舌淡红苔薄白、脉浮弱
AI：（jingfang_differentiate）
    ↳ 先弹「再确认几个细节」，再弹候选：桂枝汤（推荐，78%）/ 桂枝加葛根汤 62% / …
你：桂枝汤
AI：（jingfang_evidence）
    ↳ 结论：有文献支撑（78%）
      《伤寒论·辨太阳病脉证并治上》第12条「太阳中风，阳浮而阴弱……桂枝汤主之。」
      《伤寒论》第13条「太阳病，头痛发热，汗出恶风，桂枝汤主之。」
      PubMed：Guizhi Tang 相关研究 N 篇
AI：（jingfang_prescribe）
    ↳ 卡片：确认开方 / 先看文献依据 / 换一个方 / 暂不开方
你：确认开方
    ↳ 处方笺：桂枝三两(9g) 芍药三两(9g) 甘草二两(6g) 生姜三两(9g) 大枣十二枚
      煎服法、医嘱、用药警示、免责声明
```

如果患者说「我觉得应该清热，不该用桂枝」：

```
AI：（jingfang_discuss）
    ↳ 追问：这个看法来自哪里？最担心哪一点？
你：网上看的，怕药太热
    ↳ 我的判断不变：桂枝汤
      一、您身上的方证要点：恶风、自汗、头痛、脉浮弱
      二、原文依据：第12条、第13条
      三、现代文献：PMID …
      我理解您的顾虑：用量按 1 两=3g 折算，附煎法与禁忌…
      什么情况下我会改方：大汗、脉转微弱、服药后加重…
```

如果患者说「我怀孕两个月了」：工具会立刻判定 `revise`，列出方中妊娠禁忌药，明确认错并换方。

## 工具一览

| 工具 | 作用 | 关键返回 |
| --- | --- | --- |
| `jingfang_consult` | 分阶段问诊（intake / symptoms / symptoms2 / signs） | 更新后的 `case`、病历摘要、下一阶段 |
| `jingfang_differentiate` | 方证匹配 + 自动鉴别提问 + 候选确认 | `decided`（首选方与排序）/ `need_more`（待问要点） |
| `jingfang_evidence` | 条文核查 + PubMed 检索 | `supported` / `weak` / `modern-only` / `unsupported` + `alternatives` |
| `jingfang_formula` | 方剂详情（组成、折算、煎法、原文、禁忌） | Markdown 卡片 |
| `jingfang_prescribe` | 红旗筛查 → 文献复核 → 患者确认 → 处方笺 | `prescribed` / `blocked` / `emergency` / `declined` / `change` |
| `jingfang_discuss` | 质疑应对（守正答辩） | `maintain`（附三层依据）/ `revise`（认错改方） |

返回 `manual` 表示当前没有可用的提问界面；此时把返回的 `questions` 交给 `ask_user_question` 代问即可，流程不断。

## 方剂库

**228 首**：伤寒六经 **99 首** + 金匮 114 首 + 杂疗方 1 首 + 后世方/经验方 14 首。

宋本《伤寒论》约 112 方，库内 99 首，差的是：
- 外治法 3 首：烧裈散、大猪胆汁导、土瓜根导（非内服，单独列在 `scripts/coverage-shanghan.mjs` 的说明里）
- 佚方 1 首：禹余粮丸（宋本仅存方名，无组成）
- 其余为同名重出（如柴胡加芒硝汤、调胃承气汤在篇中重见）

`node scripts/coverage-shanghan.mjs` 可按六经列出全部方名。

仲景方与后世方在库里用 `school` 区分：`jingfang`（默认）与 `shifang`。后世方来自黄煌《经方使用手册》，开方时处方笺会明确写「本方为后世方/经验方，依据为手册方证，非仲景原文」。

### 两级数据：能开方的，和只能查的

| 档 | 数量 | 有什么 | 能做什么 |
| --- | --- | --- | --- |
| **A 档 · 可辨证** | 228 | 组成、炮制、煎服法、方证权重、文献依据、禁忌 | 参与辨证、可开方 |
| **B 档 · 名录** | 0 | 篇目、组成、主治大意 | 可查询；`evidence` 返回 `unverified`、`prescribe` 拒绝开方 |

原先 5 首只有方名与组成、没有论治文字的经方（天雄散、头风摩散、排脓散、排脓汤、蛇床子散），
已据王付《伤寒杂病论》方证讲解的【主治】补出方证，全部升为 A 档。

B 档是刻意的：**没有原文条文就不给开方**。补录条文后把 `verified: false` 去掉，即自动升为 A 档。
用 `node scripts/coverage.mjs` 可以看到每一篇收了哪些方、哪些还在名录里。

### 手册补录方的校准

`scripts/gen-shifang.mjs` 第一版是从手册文本自动推导指标（`autoPattern: true`，得分打 85 折），
问题是权重偏粗——例如温胆汤把「自汗、浮肿」也给了主症权重，八味解郁汤给了一堆 w=1 的噪声。

`lib/data/handbook-calibrated.js` 逐方重写了指标，规则：

- 手册【方证提要】/【原书方证】里点名的**特征症** → w=3（每方至少 2 条）
- 病机相关但非必备 → w=2
- 或然症、体质倾向 → w=1
- 明确相反的病机（如温胆汤忌「四肢冷、舌淡」）→ `contra`

校准后 24 首全部去掉 `autoPattern`，并加了回归测试：每首方用自身方证构造病例，必须排到首位。

### 数据来源

| 文档 | 怎么用的 |
| --- | --- |
| 《金匮要略》全文 | 逐条解析成「篇 → 条文 → 方名/组成」索引（270 条、257 方），用来核对条文、补全组成，并把原文有「论」的名录条目升为 A 档 |
| 黄煌《经方使用手册》 | 结构化抽取体质要求、适用疾病、加减法、注意事项、常用剂量，覆盖 62 首，作为**参考层**显示在方剂详情与处方笺 |
| 张锡纯加减法 | 抽取随证加减思路，覆盖 19 首，注明「张氏剂量偏重，只取思路不照搬克数」 |
| **仲圣方证合一要诀** | 抽「一句话方证 + 适用疾病 + 加减」，覆盖 114 首 |
| **王付原文** | 抽「功用 + 中医病证（方证要点）+ 西医疾病 + 用药分析 + 导读」，覆盖 195 首 |
| 黄煌手册补录 | 手册里未入库的方（后世方 + 漏收经方）自动生成 26 首：柴胡桂枝干姜汤、附子泻心汤、黄芩汤、小陷胸汤、栀子柏皮汤、栀子厚朴汤、竹叶石膏汤、温胆汤、补中益气汤、五积散、生脉散、玉屏风散等 |
| 康平本《伤寒论》 | 用于伤寒条文的异体字与版本比对（症/癥、疞/㽲、大逆/火逆等） |

前两份合并成 `patternDetail`（204 首），显示在**辨证卡**与**方剂详情**里：
候选方剂的选项描述改用「一句话方证」（如小柴胡汤：往来寒热，胸胁苦满，心烦，喜呕），
确定方剂后再展开功用、主治、参考加减——让患者选的是一个**证**，而不是一个方名。

参考层只做展示，**不参与打分、不改变开方门槛**——门槛永远是「原文条文命中 + 方证吻合度」。

### 方族鉴别（同族方不再靠猜）

同一家族的方（四逆汤类、承气汤类、泻心汤类）症状高度重叠，靠权重永远分不开。
所以 `differentiate` 在进入「选方」之前，会先检测**前五名里是否有两首以上同族**，
有就弹出该族的专属鉴别题，把答案折成「补充症状 + 加减权」：

```
问：面部颜色如何？
 · 面色苍白、没有血色          → 四逆汤 96%
 · 面赤如妆、身反不恶寒、下利清谷  → 通脉四逆汤 100%
 · 面赤、但欲寐、下利、脉微      → 白通汤 100%
 · 面赤、烦躁干呕、脉按之欲无    → 白通加猪胆汁汤 100%
```

机制在 `lib/data/families.js`：选项可带 `add`（补症状）、`boost`（本方加权）、
`demote`（同族其余方降权）——家族内部是互斥的，选中一个就该压低其余。

**选项一律说人话**：患者读得懂的写进 `label`，术语放进 `description`。

```
· 脸发红（两颧像抹了胭脂），但身上并不怕冷
   // 红只限两颧，身上反而是热的、不想盖被子
· 拉的大便里有没消化的食物
   // 中医叫「下利清谷」，吃进去什么样拉出来什么样
```

每题都有 **「说不清 / 都不像」** 出口：选了不加权、不补症状，家族鉴别只问一次就退出，
退回客观症状继续问——**不逼患者在他看不懂的选项上瞎点**。

### 文献依据分三类

| 类型 | 来源 | 标注 |
| --- | --- | --- |
| **仲景原文** | 《伤寒论》《金匮要略》条文 | `依据类型：仲景原文` |
| **后世注家方证** | 王付方证讲解的【主治】（用于原本无「论」的方） | `依据类型：后世注家方证` |
| **手册方证** | 黄煌《经方使用手册》（后世方/经验方） | `依据类型：手册方证` |

判定逻辑相同（条文命中 + 方证吻合度 ≥ 60%），但依据来源在证据卡与处方笺上都会如实标出——
**注家方证不等于仲景原文**，这一点不混着写。

### 三档剂量（不是所有方都能按 1 两 = 3 克折算）

| 档 | 适用 | 处方笺怎么写 |
| --- | --- | --- |
| `han`（115 首） | 汉制「两/铢/斤」，折算合理 | 桂枝三两（≈9g） |
| `modern`（3 首） | 宋校用「钱/分」或折算明显不合临床，如防己黄芪汤、麻杏薏甘汤 | 直接经验剂量，注明「现代经验剂量」 |
| `ratio`（18 首） | 等分/比例配伍的丸散，如十枣汤、硝石矾石散、乌梅丸、五苓散 | 折算列「—」，注明「按原方比例」 |

另有 `doseCap`：保留汉制原量但给出现代上限（如大青龙汤、越婢汤的麻黄六两≈18g，提示临床减至 6–9g）。
`node scripts/audit-doses.mjs` 会扫出「<2g / >30g 的可疑折算」和「该标比例却硬折」的方。

### 性别与情境：方证对应，不是身份对应

**绝不能因为性别否定一首方。** 桂枝茯苓丸治男性前列腺增生/慢性前列腺炎、当归芍药散治男科杂病、温经汤治男性更年期，都是正经用法——判断依据是有没有这组方证。

引擎因此只区分两类，都不看性别：

| 类型 | 含义 | 例子 | 效果 |
| --- | --- | --- | --- |
| `requires`（事实前提） | 没有这个事实，方就不成立 | 安胎：当归散、白术散、葵子茯苓散；金疮：王不留行散 | 不进候选 |
| `contexts`（情境加权） | 有这个情境时优先考虑，没有也不排除 | 产后：竹叶汤、竹皮大丸、下瘀血汤；妊娠：干姜人参半夏丸、当归贝母苦参丸 | 命中 +0.06 |

问诊 `intake` 会采集「特殊情况」（妊娠/产后/哺乳/经期/围绝经/术后/外伤/年老），只作加权线索。
桂枝茯苓丸的指标也从「妇科病」改成了「方证」：少腹急结、腹中包块、舌暗紫、脉涩、经行腹痛、小便不利、尿频——男女通用。

## 已知边界

- PubMed 只覆盖英文文献；中文文献（知网/万方）未接入，工具会如实说明。
- 条文按宋本《伤寒论》与通行本《金匮要略》录入，个别条号建议以原书核对；《金匮》方按篇名引用，未标条号。
- 伤寒补遗 45 首**全部完成人工校准**（34 首见 `shanghan-calibrated.js`，11 首直接手写），已无 `autoPattern` 降权。
- 金匮 A 档 113 首，名录归零（5 首无「论」的方已按注家方证补录，证据类型标注为「后世注家方证」）。
- 手册补录的 24 首已**人工校准**方证指标（主症 w=3 / 兼症 w=2 / 或然 w=1），并补了相反见症；不再有 `autoPattern` 降权。
- 手册里另有 17 首没能入库：多数是「合方/加减方」（柴归汤、半张防风通圣散等），手册本身没给组成；少数是方证信息不足以推导辨证指标。
- 黄煌/张锡纯的经验只覆盖常用方（62/19 首），金匮冷僻方暂无参考层。
- `patternDetail` 覆盖 147/155 首；剩余 8 首在两本书里没有对应条目。
- 王付原文的「方歌」「用法」尚未抽取，暂时只用了导读/功用/主治/用药分析。
- 患者自填的舌象、脉象只能作参考（尤其脉象需医师诊察），插件在提问文案里已注明。
- 辨证是规则引擎，不是大模型自由发挥；规则覆盖不到的证型会返回 `insufficient`，此时应线下就诊。
